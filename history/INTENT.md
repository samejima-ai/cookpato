# 意図ログ

本ファイルは Cookパト の現役機能の「なぜこの条件で存在するのか」を記録する。
SPEC.md が「WHAT」を、本ファイルが「WHY＋却下案」を担う役割分担とする。
初期化サイクル（2026-05-12）では SPEC.md と過去 PR を一次情報源として最小エントリで開始し、
次サイクル以降の機能追加・変更で漸次エントリを増やす。

---

## 機能ID: F001 - カレンダー無限スクロール

- **状態**: 現役
- **追加日**: 初回献上時（2026 年 4 月、PR #1 系列）
- **意図**: メモ帳の「日付・曜日フォーマットを毎月手作業で作る」不満を解消するため、画面遷移なしで連続閲覧できるカレンダーを単一画面に提供する
- **条件根拠**:
  - 月切替ボタンを置かない → 「ボタンが増えるとメモ帳の手軽さが損なわれる」原則
  - 当日が中央付近に来る自動スクロール → 起動直後の操作コストをゼロにする
  - 遠方の日の描画は遅延可だがデータは即保持 → 軽快感と整合性の両立
- **却下案**:
  - 月ビュー固定（カレンダー UI 標準）: 月切替操作が増え DONT.md「画面遷移なし」「登録ボタン排除」原則に反する
  - 仮想スクロール（react-window 等）導入: 依存追加のコスト > 得られる軽さ。手書きの IntersectionObserver で十分
- **関連**: F002, F009, F010
- **確度**: 確定

## 機能ID: F002 - フリー入力（料理行＋ちょいメモ）

- **状態**: 現役
- **追加日**: 初回献上時
- **意図**: メモ帳の「自由記述」体験を最優先で保ち、カテゴリ・料理名統一を一切強制しない
- **条件根拠**:
  - 1行1品ルール → 完了トグルの粒度を確定させるため
  - 即時保存（保存ボタンなし） → DONT.md の最大不満点だった「登録操作の多さ」を撤廃
  - **uncontrolled input + key={dateKey} 再マウント** → iOS Safari のフリック入力多重反映バグ回避（IME 未確定文字消失防止）
  - ちょいメモを料理行と分離 → 検索・完了トグル・週達成判定の対象外にして「日付直下の自由メモ」を独立確保
- **却下案**:
  - controlled input: iOS Safari × IME 多重反映でカーソル位置喪失・文字消失。`docs/IOS-SAFARI-NOTES.md` 参照
  - 主菜／副菜カテゴリ欄分離: DONT.md「カテゴリ分け排除」に反する
- **関連**: F003, F005, F006
- **確度**: 確定

## 機能ID: F003 - 完了トグル（品単位）

- **状態**: 現役
- **追加日**: 初回献上時
- **意図**: ストック料理中心の運用で「品ごとに作った／まだ」を即記録する
- **条件根拠**:
  - 44×44px ヒット領域（iOS HIG 準拠） → 調理中のぬれ手・油汚れ手タップで誤爆しない最小サイズ
  - チャタリング 300ms 防止 → 震え手の二重タップで状態反転を防ぐ
  - 完了行は文字色グレー＋チェックボックスのグレー塗り → 未完了行との相対コントラストで「次に作るもの」を主眼化
  - 行内容変更で完了状態リセット許容 → 完了済みを後から編集する運用がないため、行番号配列管理で十分
- **却下案**:
  - 行左 1/3 占有のヒット領域（旧設計）: 料理名表示幅を圧迫したため 44×44px 正方形へ変更
  - 日単位まとめトグル: 品ごとの完了管理に粒度が粗すぎる
- **関連**: F002, F004, F005
- **確度**: 確定

## 機能ID: F004 - 行削除 UI（長押し → 揺れ → ✕ → 確認ダイアログ）

- **状態**: 現役
- **追加日**: 初回献上時
- **意図**: テキストエリアでの改行削除はキーボード操作で調理中に手間。タップ操作だけで 1 品削除できる導線を確保する
- **条件根拠**:
  - ✕ ボタン通常時非表示 → 料理名表示幅を最大化
  - 長押し 500ms → 揺れ演出 → iOS ホーム画面と同じメンタルモデル
  - 確認ダイアログ必須 → 誤削除リカバリ不可（自動バックアップ A 層からの復旧は次回起動時のみ）
  - 削除モードは 1 行のみアクティブ → 同時揺れ抑制で誤爆防止
- **却下案**:
  - スワイプ削除（iOS 標準ジェスチャ）: 縦無限スクロールと干渉するため不採用
  - ✕ 常時表示: 「使わない機能が画面にある UI を悪化させる」DONT.md 基本原則に反する
- **関連**: F003
- **確度**: 確定

## 機能ID: F005 - お気に入りマーカー（先頭トークン共通）

- **状態**: 現役
- **追加日**: 拡張サイクル（PR 系列で追加）
- **意図**: 「これ良かった／定番」を本人だけに分かる印として残す。同一料理は表記揺れがあっても自動共通マーキング
- **条件根拠**:
  - 先頭トークンの正規化キーで判定 → 「豚バラもやし 味噌」も「豚バラもやし」も同キー扱い、補足違いを許容
  - 漢字⇔かな統一は**しない** → 検索ロジックと挙動を揃える、過剰な変換で誤マッチ防止
  - マーカー表示のみ・検索フィルタなし → DONT.md「使わない機能が画面にある UI を悪化させる」
  - ストック側へはハート表示のみ追従、トグルなし → 管理場所をカレンダー側に一本化
- **却下案**:
  - 全文一致でのマーキング: 表記揺れ（「豚バラ」と「豚ばら」）で別扱いになり実用性低い
  - お気に入り専用一覧画面: DONT.md「画面遷移なし」原則に反する
- **関連**: F002, F008
- **確度**: 確定

## 機能ID: F006 - 過去履歴検索

- **状態**: 現役
- **追加日**: 初回献上時
- **意図**: メモ帳ではできない「豚バラ大根前いつ作った？」を解決する
- **条件根拠**:
  - オーバーレイパネル方式 → カレンダー表示を阻害しない、検索欄空で結果非表示
  - ひらがな/カタカナ相互マッチ → 妻の表記揺れを吸収
  - 完全一致 → 類似一致の順、日付降順 → 「最近作ったか」が最も知りたい情報
  - 最大 20 件 → スクロール可能だが無限スクロール導入は過剰
- **却下案**:
  - 全文検索ライブラリ（Fuse.js 等）導入: 依存追加に見合う精度向上なし、月数百件規模では線形走査で十分
  - 漢字⇔かな統一の検索: 誤マッチ増加、F005 とも整合性損なう
- **関連**: F002, F005
- **確度**: 確定

## 機能ID: F007 - バックアップ二層（A: localStorage 二重化 / B: 週1ファイル書き出し）

- **状態**: 現役
- **追加日**: 拡張サイクル（過去にストック消失の実例あり）
- **意図**: iOS の自動ストレージ削除・アプリ内バグでのデータ消失からデータを守る。失うとユーザー体験を著しく損なうストック・累積メダル等を保護
- **条件根拠**:
  - A 層: 起動時 1 日 1 回スナップショット、実質空検出で自動復元 → 無音・完全自動で妻の認知負荷ゼロ
  - B 層: 週 1 バナー + `<a download>` 方式 → iOS Safari の File System Access API 非対応制約下で最小タップ数
  - クリック発火 = 成功とみなす → OS ダイアログのキャンセル検知不可、UX シンプル優先
  - 蓄積型（同一ファイル上書きしない） → 月またぎ復元要求に対応、年 52 ファイル × 数 KB で容量問題なし
- **却下案**:
  - クラウド同期: DONT.md「完全ローカル原則」に反する。過去事故契機でも除外維持
  - 自動ファイル書き出し: iOS Safari ユーザージェスチャ必須制約により不可
  - IndexedDB 採用: 単一ユーザー・小データ量で localStorage の単純さが勝る
- **関連**: 全機能（データ永続化の基盤）
- **確度**: 確定

## 機能ID: F008 - ストックリスト（永続・常時表示）

- **状態**: 現役
- **追加日**: 初回献上時
- **意図**: 冷凍ストック・下味付き料理の管理を月またぎで保持し、画面下部常時表示でいつでも確認できる
- **条件根拠**:
  - 名前 + 個数の組 → 「下味豚 × 3」のような複数個運用が前提
  - `[−][個数][＋]` 構成 + 個数 0 で赤い削除ボタン化 → 「削除までは 2 アクション」で誤削除を防ぎつつ専用 ✕ を排除
  - 36×36px の例外（HIG 44px 下限を下回る） → 3 要素密接配置で誤爆耐性高、名前領域確保が優先（CLAUDE.md UI 規約参照）
  - 長押しドラッグ並び替え → `[↑][↓]` ボタン廃止、料理行と同じメンタルモデル
  - `useAutoShrink` で 1 行縮小表示 → 折り返し禁止（CLAUDE.md「1行表示原則」）
- **却下案**:
  - 個別 ✕ ボタン常時配置: 「削除ボタンが常時視界にある UI を避ける」設計思想に反する
  - 別画面でストック管理: DONT.md「画面遷移なし」原則に反する
- **関連**: F005, F007
- **確度**: 確定

## 機能ID: F009 - 週達成「頑張ったね」表示

- **状態**: 現役
- **追加日**: 拡張サイクル
- **意図**: 日〜土の 7 日が埋まった週に対し、妻の達成感を「累積カウンタ」と「達成演出」の 2 表現で支える
- **条件根拠**:
  - 累積カウンタはフロート金メダル（左下、`pointer-events: none`） → 編集・スクロールを阻害しない
  - 一度入ったキーは減らない → 妻の「献血カウント」セマンティクス
  - 達成演出は「未達成 → 達成」遷移の瞬間のみ、blur 時評価 → 1 文字入力中の誤発火防止
  - 既登録週は再発火しない → 編集し直しでも演出ノイズなし
- **却下案**:
  - 達成週一覧画面: 「本人の静かな達成感に留め、外向きの実績化は意図しない」
  - リセット機能: 「積むのが目的」のため
- **関連**: F002
- **確度**: 確定

## 機能ID: F010 - 空状態応援表示（シマエナガ装飾）

- **状態**: 現役
- **追加日**: 拡張サイクル
- **意図**: 「これから何作ろう」を前向きに捉えるための視覚ヘルパー、純粋な装飾
- **条件根拠**:
  - today〜today+6 の空日のみ → ウィンドウ起点を today に固定、過去日は対象外
  - 未来全域に拡げない → 「未計画が大量にある」プレッシャーを生み逆効果
  - 2 秒周期で水平反転 → ぱたぱた演出、`aria-hidden` でアクセシビリティ意味は持たせない
- **却下案**:
  - 検索フィルタ・専用一覧で空日を機能的に操作させる UI: 応援装飾の意図と矛盾
  - 複数ウィンドウ連鎖で遠未来も拾う: 上記理由で逆効果
- **関連**: F001
- **確度**: 確定
